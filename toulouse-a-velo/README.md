# Toulouse à vélo — トゥールーズ自転車散歩

実在のフランス・トゥールーズの街を 3D で再現し、自転車で自由に走り回れるブラウザゲームです。
建物・通り・川・橋・公園・街路樹は、すべて実際の地図データ（OpenStreetMap と IGN BD TOPO）から自動生成しています。
「本物そっくりモード」（標準）では、IGN（フランス国土地理院）が航空機からレーザーで測った **LiDAR HD** の高さデータで
屋根の形・地形・木・橋を実測どおりに作り、地面と屋根に**本物の航空写真**を貼ります。API キーや登録は要りません。

## エリア

| エリア | 範囲 | 読み込み方 |
| --- | --- | --- |
| **トゥールーズ全体**（標準） | ポン・ヌフから半径 5 km（10 km 四方、建物 13 万棟）。旧市街に加えて、西のパーパン（病院・ローマ円形闘技場）、サン・シプリアン、ミニム、ランギュイユ、東のシテ・ド・レスパスまで | 自転車の周り（約 650 m）だけを詳しく作り、走るにつれて読み込む。遠くは粗い高さに航空写真を貼った遠景 |
| 旧市街 | キャピトル広場から半径 1.2 km | まとめて読み込む。「地図から生成」の見た目も選べる |
| 軽量 | キャピトル周辺の半径 0.7 km | 古い PC・スマホ向け |

**トゥールーズ全体のしくみ**: エリアを 500 m 四方のタイル（420 枚）に分けます。
- 道路・川・公園・名所はエリア全体を最初に読み込むので、ナビ・地図・通りの名前はどこでも使えます。
- 建物・LiDAR の屋根・木・橋・高解像度の航空写真は、自転車の近くのタイルだけを組み立て、離れたら捨てます。読み込みが間に合わないときは、その場で少し待ちます。
- 遠景は、エリア全体の粗い表面モデル（10 m 格子）に航空写真の全体図を貼ったものです。
- 隣り合うタイルの LiDAR は、エリア共通の格子から切り出しているので、境目で地面がずれません。

## 2 つの見た目

| 見た目 | 中身 |
| --- | --- |
| **本物そっくりモード**（標準） | IGN LiDAR HD の表面モデル（屋根・木・橋の上面の高さ）と地形モデル（地面の高さ）から、屋根の形・地形の起伏・1 本 1 本の木・橋の高さを実測どおりに作る。地面・屋根・橋面には IGN の航空写真（BD ORTHO、20 cm 解像度）を貼る |
| **地図から生成** | 地図データ（建物の形・高さ・屋根の高さ・材料）から 3D を組み立てる。屋根・地面・壁の模様は自動生成。軽くて古い PC 向け |

タイトル画面の「本物そっくりモード」のチェックで切り替えます。どちらでも当たり判定・ナビ・通りの名前・名所は同じ地図データで動きます。
本物そっくりモードでは地面の高さも本物なので、ガロンヌ川沿いの低い遊歩道（ベルジュ）や橋の上り下りもそのまま走れ、坂では速度が変わります。
LiDAR が取得できなかったときは、自動で「地図から生成」に切り替えて始めます。

## 「正確な再現」のしくみ

地図データは 2 つの公開データから取得します。

1. **OpenStreetMap**（Overpass API）＋ **IGN BD TOPO の実測の建物の高さ** … 通常はこちら
2. **IGN BD TOPO だけ** … OpenStreetMap のサーバー（Overpass API）が混んでいてつながらないと自動でこちらに切り替わります。タイトル画面の「グラフィック設定」で最初から選ぶこともできます

IGN（フランス国土地理院）の BD TOPO は、建物の軒の高さ・屋根の高さ・壁や屋根の材料（レンガ・石・コンクリート／瓦・スレート）、道路の幅・正式な通り名・橋・歩行者専用道まで持っている公的なデータです。

| 要素 | データ | 再現方法 |
| --- | --- | --- |
| 建物の形 | OSM（フランスの地籍図由来）または IGN | 外形を押し出して 3D 化。中庭（穴）、`building:part`（鐘楼など）にも対応 |
| 建物の高さ | ① OSM の `height` → ② **IGN の実測の高さ** → ③ OSM の階数 → ④ 推定 | IGN は航空写真測量による実測値（IGN で組み立てた旧市街エリアでは 12,307 棟中 99.7% が実測） |
| 屋根 | OSM の `roof:shape`、IGN の屋根の最高点・最低点 | 四角形の建物は実際の屋根の高さで切妻・寄棟に。それ以外は屋根の中間の高さの陸屋根 |
| 壁（ファサード） | IGN の壁の材料（レンガ・石・コンクリート） | 実際の街並みの写真を手本にした 8 つの様式から材料に合わせて選ぶ: 薄いレンガ（brique foraine）に白い石の窓枠、レンガに木の鎧戸と鉄の手すり、黄土色・灰緑・サーモン色・ばら色の漆喰にレンガの窓枠（レンガと石の交互積み）、クリーム色の切り石、現代的な建物。1 階は馬車門・店・鉄格子の窓・玄関・壁付けの角灯。窓は壁の辺の中央にそろえ、最上階の窓が軒で切れないよう階の高さを調整 |
| キャピトル | 広場に面した建物の壁 | 専用の正面: 1 階はレンガと白い石の縞、2 階はばら色のレンガに白い付け柱、中央に 8 本のばら色の大理石の円柱と「CAPITOLIUM」の破風、屋上の手すりと壺 |
| 教会 | IGN の建物の種類（教会） | 南仏のレンガの教会の壁（白い石の帯・控え壁・半円アーチの高窓・軒下の小窓） |
| 鐘楼 | 表面モデルの最も高い点（尖塔の位置と高さ）と屋根の高さ | サン・セルナン（半円アーチ 3 層＋ミトラ形アーチ 2 層・小塔の冠・石の尖塔）とジャコバン（ミトラ形アーチ 4 層）の八角形の鐘楼を、写真を手本にモデルで作る |
| 屋根の色 | OSM の `roof:colour` など、IGN の屋根の材料 | 地図から生成のときは瓦・スレートなどの色（本物そっくりモードでは航空写真） |
| 道路 | OSM の `highway`、IGN の道路の種類・幅・通り名 | 車道・歩道・歩行者専用道（石畳）・自転車道を描き分け、実際の通り名を表示 |
| 川・運河 | 水域ポリゴン | ガロンヌ川は約 6 m 下を流れ、レンガの河岸の壁で囲まれる。橋だけ渡れる（橋の下で切り抜かれた水面は埋め直す） |
| 公園・木 | OSM の `leisure` / `natural=tree`、IGN の公共空間・植生 | 登録された木はその位置に。木の少ない公園には木を補う。IGN だけのときは並木道（Allées・Boulevard など）に木を植える（推定） |
| 通路 | 道路が建物の外形を横切る箇所 | 建物の下をくぐる通路として通れるようにする |

本物そっくりモードでは、さらに次のデータを使います（どちらも IGN の公開データ、Licence Ouverte）。

| 要素 | データ | 再現方法 |
| --- | --- | --- |
| 屋根の形 | LiDAR HD の表面モデル（MNS、約 1 m 格子） | 建物の外形の内側を、屋根の高さが変わる所にだけ点を置いて制約付きドロネー三角形分割（poly2tri）。切妻・寄棟・マンサード・中庭・鐘楼の尖塔まで実測の形になる。外形の縁は前後の中央値でならして、煙突や樋のぎざぎざを消す |
| 地形 | LiDAR HD の地形モデル（MNT、約 2 m 格子） | 地面を起伏のある格子にし、壁は地面から立ち上げる。自転車とカメラは地面の高さに沿って走る |
| 木 | 表面モデル − 地形モデル（樹冠の高さ） | 樹冠の頂点を探し、本物の位置・高さ・枝の広がりで木を置く（旧市街エリアで約 1.2 万本）。建物の上は除き、中庭の木は残す |
| 橋 | 表面モデルの橋の上の高さ | 橋面の高さの断面を作り、川や道の上の高い所は橋脚の間をレンガのアーチにする。ポン・ヌフのように、アーチの縁と水切りは白い石、橋脚の上に丸い穴（ドゥグロワール）、石の手すり付き。ポン・ヌフは川面から約 13 m の高さ |
| 水面 | 地形モデル（川面の高さ） | 川・運河ごとに水面の高さを決め、橋の下も水面でふさぐ（航空写真に写った橋が川面に見えないように） |
| 地面・屋根・橋面の色 | 航空写真（BD ORTHO HR） | 約 250 m の区画ごとに WMS で取得し、近くの区画ほど高解像度（約 15 cm/ピクセル）に差し替える。目の高さでぼやけないよう、近くだけ細かい凹凸を重ねる |

ゲーム中に `Esc` でポーズすると、建物の高さが「IGN 実測 / OSM / 推定」のどれから来たかの内訳が見られます。

### 既知の限界

- 壁（ファサード）は真上からの航空写真には写らないので、窓・扉は実際の街並みを手本に手続き的に描いた様式です。建物ごとの本当の窓の配置や色ではありません（キャピトルの正面だけは専用）。教会などのモニュメントの装飾は再現されません。
- 航空写真には撮影時の車・影・催し物のテントなどもそのまま写っています。橋の下の川面には橋そのものが写っているので、水面はやや不透明にしています。
- 橋のアーチは実測ではなく、約 26 m おきの一般的な形です（白い石のアーチの縁・橋脚の丸い穴「ドゥグロワール」・石の手すりはポン・ヌフ風に付けています）。
- 旧市街エリアの本物そっくりモードは約 230 万三角形あります。トゥールーズ全体でも、自転車の周りだけでおよそ 150 万三角形を使います。古い PC やスマホでは「軽量」エリアを選んでください。
- トゥールーズ全体では「地図から生成」の見た目は使えません（本物そっくりモードだけ）。遠景には個々の建物の形はありません。
- 「地図から生成」では地形（標高差）は再現していません。
- 自動車・歩行者はいません。一方通行も無視します（ゲームなので）。
- 再現の精度は元データに依存します。IGN だけのときは、サン・セルナンの鐘楼のような建物の細かな部分（`building:part`）や個々の街路樹はありません。OSM のおかしな箇所は [OpenStreetMap](https://www.openstreetmap.org/) を直すと、次回のデータ取得から反映されます。

## 開発

```bash
cd toulouse-a-velo
npm install
npm run dev          # http://localhost:5173 で起動
```

初回起動時、ブラウザが Overpass API（OSM）と IGN Géoplateforme の WFS から地図データをダウンロードします（30 秒〜数分）。Overpass に 100 秒つながらなければ IGN だけで組み立てます。取得したデータは IndexedDB にキャッシュされ、2 回目以降はすぐに始まります。

### 地図データを同梱する（推奨）

```bash
npm run fetch-data -- toulouse      # トゥールーズ全体 → public/data/toulouse.json（道路など）と
                                    #   public/data/toulouse-tiles/<i>_<j>.json（建物、500 m ごと・約 80 MB）
npm run fetch-data -- centre        # 旧市街 → public/data/centre.json（OSM、だめなら IGN）
npm run fetch-data -- all           # すべてのエリア
npm run fetch-data -- centre --ign  # IGN だけで作る（旧市街で約 8 MB、1 分ほど）
```

`public/data/` に保存されたデータがあれば、ゲームはそれを最初に使います（ダウンロード待ちなし）。データファイルは大きいので Git には入れていません（GitHub Pages への公開時に自動で取得します）。

### URL パラメータ

| パラメータ | 例 | 説明 |
| --- | --- | --- |
| `area` | `?area=light` | エリアを選んだ状態で開く（`toulouse` / `centre` / `light`） |
| `lat` `lon` `r` | `?lat=43.5615&lon=1.4682&r=800` | 任意の地点を中心にする（トゥールーズ以外の街でも動きます） |
| `mode` | `?mode=tour` | タイムアタックを選んだ状態で開く |
| `autostart` | `?autostart=1` | タイトル画面を飛ばして開始 |
| `real` | `?real=0` | 「地図から生成」で開く（本物そっくりモードを切る） |

### テスト

```bash
npm test                           # 単体テスト（座標変換・OSM/IGN の変換と解析・ルート探索・当たり判定・LiDAR の屋根と木）
npm run build && npm run test:e2e  # ブラウザでの通しテスト（合成の地図・LiDAR・航空写真）
npm run test:autopilot             # 本物の地図で、全名所を自動走行で回れるか（要 fetch-data）
LIDAR=1 NODE_USE_ENV_PROXY=1 npm run test:autopilot  # 同じことを LiDAR の地形・橋の高さの上で
npm run build && node test/e2e-network.mjs  # 本物のネットワークで IGN への自動切り替えを確認
npm run build && NODE_USE_ENV_PROXY=1 node test/real-mode.mjs '[{"name":"a","lm":"saint-sernin","camera":"drone"}]'
                                   # 本物の LiDAR・航空写真で開いて指定の場所を撮影（test/output/）。
                                   # AREA=toulouse でトゥールーズ全体（タイルの読み込みも確認）
```

- `test:e2e` は地図サーバーへの通信を合成データ（`test/fixture.mjs`、トゥールーズ風の格子状の街）に差し替えて、読み込み → 走行 → 建物・川との衝突 → 橋 → 地図とナビ → タイムアタックを確認し、`test/output/` にスクリーンショットを保存します。本物そっくりモードも合成の LiDAR（標高の BIL）と航空写真で、地面・屋根・橋の高さと木の検出を確認します。
- `test:autopilot` は本物のトゥールーズの上で、ゲームのナビに沿ってタイムアタックのコースと 18 か所の名所すべてを自動走行します（約 15 km）。道が建物でふさがっていないか、川で行き止まりにならないかの確認になります。

### 公開（GitHub Pages）

`.github/workflows/toulouse-a-velo.yml` が `main` ブランチへの push でビルドし、地図データを同梱して GitHub Pages に公開します。リポジトリの **Settings → Pages → Source** を **GitHub Actions** にしてください。
